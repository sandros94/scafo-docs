# Celld runtime

> How a node picks the Celld binary, what it passes to every runtime process, and which variables it refuses to let you set.

Scafo requires Celld **0.4.1**, and checks: `scafo sail` runs `<binPath> --version` before it opens the bucket and refuses an older or unreadable binary with `capability-missing`. Each environment assigned to a node runs as one Celld process, started by the node's reconcile loop and stopped by it. Scafo owns the process arguments and part of its environment; everything else is upstream Celld policy, which you write through this node's configuration.

## Choosing the binary

| File key | Env | Flag | Default |
|---|---|---|---|
| `runtime.binPath` | `SCAFO_CELLD_BIN` | `--celld-bin` | `celld` |

The value is resolved against `PATH` unless it contains a directory separator. The official image ships `/usr/local/bin/celld`; the installer writes `SCAFO_CELLD_BIN=/usr/local/bin/celld` into the node's systemd unit. The same binary runs deploy builds, so a node whose `binPath` is wrong fails both at reconcile and at deploy time.

## Node-wide Celld policy

Variables handed to every runtime process this node starts:

| File key | Env | Flag |
|---|---|---|
| `runtime.celldEnv` | `SCAFO_CELLD_ENV` | `--celld-env` |

Two spellings, as with node labels:

::code-group

```jsonc [scafo.config.jsonc]
{
  "runtime": {
    "celldEnv": {
      "CELLD_MAX_RSS_MB": "512",
      "CELLD_MAX_RESIDENT_CELLS": "64",
    },
  },
}
```

```sh [environment]
SCAFO_CELLD_ENV=CELLD_MAX_RSS_MB=512,CELLD_MAX_RESIDENT_CELLS=64
```

```sh [flag]
scafo sail --celld-env CELLD_MAX_RSS_MB=512,CELLD_MAX_RESIDENT_CELLS=64
```

::

Rules for the set:

- The inline form (flag or environment variable) **replaces the config file's set wholesale**; it does not merge into it.
- A value may not contain a comma in the inline form — the separator wins. Write such a value as `runtime.celldEnv` in the config file, which has no such limit.
- Everything after the first `=` is the value, so `NAME=a=b` gives `a=b`. Surrounding spaces are dropped on both halves.
- Names are letters, digits and underscores, never beginning on a digit. Values must be strings: a number or a boolean in the config file is refused rather than stringified.
- A duplicate name is refused rather than resolved. Text that names no variable at all is refused too.

Scafo adds no Celld policy defaults of its own. Whatever upstream Celld defaults to is what a process gets, apart from the telemetry switch below.

## Names Scafo refuses

Setting any of these through `runtime.celldEnv` is `invalid-input` ("Reserved environment variable"), refused at load rather than silently overwritten, because the driver writes them itself from this node's configuration and from the listeners its processes bind:

| Variable | Why |
|---|---|
| `AWS_ACCESS_KEY_ID` | derived from `bucket.accessKey` |
| `AWS_SECRET_ACCESS_KEY` | derived from `bucket.secretKey` |
| `AWS_SESSION_TOKEN` | reserved with the rest of the credential set the driver writes |
| `AWS_REGION` | derived from `bucket.region` |
| `CELLD_BUCKET` | derived from the bucket, prefix and this environment's fleet prefix |
| `CELLD_ADDR` | derived from `runtime.bindHost` and the allocated public port |
| `CELLD_INTERNAL_ADDR` | derived from `runtime.bindHost` and the allocated internal port |
| `CELLD_ADVERTISE` | derived from the node's advertised address and the internal port |
| `CELLD_TRUST_FORWARDED_HEADERS` | derived from the ingress topology |

Every other Celld variable is accepted as-is and handed to every process this node starts. Scafo keeps no list of its own: what a variable does, and which release introduced it, is upstream Celld's documentation. These are the **node's** Celld policy, not an application's variables: an application's variables travel in its own `wrangler.jsonc` or `wrangler.json`, inside the artifact, and the node never touches them.

## What Scafo passes to each process

### Arguments

| Argument | Value |
|---|---|
| `--bucket` | `<bucket.bucket>/<bucket.prefix>/fleets/<project>/<env>` — the prefix segment is omitted when none is configured |
| `--endpoint` | `bucket.endpoint` |
| `--listen` | `<runtime.bindHost>:<public port>` |
| `--internal-listen` | `<runtime.bindHost>:<internal port>` |
| `--advertise` | `<advertised host>:<internal port>` |

Ports come in `public`/`internal` pairs from the node's range, starting at `runtime.portRangeStart` (`42000` by default, `42000`–`42998`). The advertised host is `node.advertise`'s host when one is set, and `node.listen`'s host otherwise — that is what a peer dials to reach the process that owns a cell, which is why a multi-node fleet needs `runtime.bindHost` off loopback and a stated transport.

Each environment's Celld fleet state lives under `fleets/<project>/<env>` in the same bucket, outside the `_scafo` registry root.

### Environment

Three steps, each overriding the last — and that is the whole of it:

1. **Base**: `PATH`, `HOME`, `TMPDIR`, `TZ` and `RUST_LOG`, copied from the daemon's own environment when they are set — nothing else of the daemon's environment reaches a runtime process.
2. **Your policy**: everything in `runtime.celldEnv`.
3. **Derived, non-overridable**: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_REGION` from the node's bucket configuration, and `CELLD_TRUST_FORWARDED_HEADERS=1`, because the ingress in front of the node terminates TLS and supplies the forwarded headers.

Nothing belonging to one environment is added: a runtime process's environment is the same for every environment this node serves, apart from the arguments above.

::warning
Celld child processes therefore hold the fleet's bucket credentials. Scafo provides no OS credential boundary around them.
::

### Variables per application

An application's variables are not in the process environment at all: they live in the application's own `wrangler.jsonc` or `wrangler.json`, under `vars`, and Celld reads them from the config it was published with. The node hands that file to Celld exactly as the artifact carried it.

::read-more{to="/docs/deploying#variables"}
Setting them at deploy time with `scafo deploy --var`, and what that means for secrets.
::

## Shutdown grace

`CELLD_SHUTDOWN_TOTAL_MS` is Celld's complete process shutdown bound. Scafo reads it out of `runtime.celldEnv` — not out of the daemon's own environment — and sizes its supervisor grace from it:

```
supervisor grace = CELLD_SHUTDOWN_TOTAL_MS + 5000 ms
```

With the upstream default of `40000` that is a **45-second** grace between `SIGTERM` and the supervisor's hard kill, so a process always finishes draining before it is killed. The value must be a positive integer of digits only, no greater than `2147478647`; anything else is `invalid-input` ("Invalid celld shutdown bound").

Whatever supervises the node has to be more patient than the node is with its children:

| Supervisor | Setting |
|---|---|
| Docker / Compose | `stop_grace_period: 50s` |
| systemd | `TimeoutStopSec=50s`, `KillMode=mixed`, `KillSignal=SIGTERM` |
| Anything else | at least 50 seconds, or `CELLD_SHUTDOWN_TOTAL_MS + 10s` when you raised it |

::important
Signal the daemon alone, in a private PID namespace, and let it drain: it stops its runtimes itself, in an order that matters. A supervisor that signals every process beside it defeats the drain.
::

## Telemetry

`CELLD_OTEL` is the one Celld variable Scafo defaults for you. With `observability.enabled` on and no `CELLD_OTEL` in `runtime.celldEnv`, every runtime process is started with `CELLD_OTEL=1`. Set it yourself in `runtime.celldEnv` — to another value, or to `0` — and your value stands; unlike the reserved names above, this one may be overridden.

::read-more{to="/docs/observability"}

## Lease cadence

Each runtime process holds a node lease in its fleet prefix and renews it every third of `CELLD_TTL_MS` (default `10000`). A renewal that fails or times out is retried before the authority expires: Celld keeps the normal cadence while at least half of the remaining lifetime is left, and otherwise retries after a quarter of what remains. A process whose lease expires, disappears, or no longer matches what it published fences itself — it stops its cells and exits with code 3 — and the node restarts it. The log line starts with `SELF-FENCE:` and carries one of `node_lease_watchdog_fence`, `node_lease_record_missing_fence` or `node_lease_record_mismatch_fence`.

Change the lifetime consistently on **every** node of the fleet; an unplanned takeover waits up to the lifetime:

```jsonc [scafo.config.jsonc]
{
  "runtime": {
    "celldEnv": { "CELLD_TTL_MS": "30000" },
  },
}
```

`RUST_LOG=celld=info,store=debug` in the daemon's environment — one of the variables it hands to every runtime process — makes each process log every read and write of its own lease record with an `outcome` of `found`, `missing`, `applied`, `rejected` or `error`.

## Startup storage test

Before a runtime process serves, Celld tests the bucket: the four conditional writes and one ranged read, on throwaway objects under `probe/` in the environment's fleet prefix. A store that rejects a required operation, ignores a condition, or returns the wrong range stops the process at once. An operation that fails without a clear cause is retried up to three times, after which the process starts with a warning. `CELLD_STORAGE_PROBE=0` in `runtime.celldEnv` skips the test.

Scafo's bootstrap probe under `_scafo/probe/` tests a ranged read as well, so a store that mishandles `Range` is refused once, at `scafo sail`, before any process starts. Celld's test is its own and runs per process regardless.

## Upstream documentation

Celld owns deployment adoption, application health, cells and runtime resource policy. Read its own notes before upgrading a fleet:

- [Celld security guidance](https://github.com/denoland/celld/blob/main/docs/security.md) — its internal operator API is mostly unauthenticated; keep it on a private network or overlay.
- [Celld limitations](https://github.com/denoland/celld/blob/main/docs/limitations.md)
- [Cloudflare compatibility](https://github.com/denoland/celld/blob/main/docs/cloudflare-compat.md)

Celld exposes one current deployment per fleet. Scafo records a monotonic deployment revision rather than a selected version, and offers no old-build routing or historical deployment selector — see [Celld issue #181](https://github.com/denoland/celld/issues/181).

::note
`/.well-known/celld/health` is the application runtime's health endpoint. The node's own is `/.well-known/scafo/health`.
::
