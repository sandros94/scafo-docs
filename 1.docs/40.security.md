# Trust model and limitations

> A description of the boundary Scafo draws, the surfaces it exposes, and what it does not do. This is a description, not an audit.

## Trust model

One Scafo installation is **one trusted workload domain**. Repositories, dependencies, build inputs, deployers, runtime code and operational credential holders must trust one another.

Project, operator and OIDC scopes **authorize** actions. They do not **isolate** hostile workloads.

::important
Do not use one installation for arbitrary customer code, public build submission, or mutually untrusted projects. Use separate installations, buckets, and host or VM boundaries for separate trust domains.
::

## Protected surfaces

| Surface | Auth | Notes |
|---|---|---|
| `/.well-known/scafo/health` | none | Intentionally public. |
| `/v1/ingress/ask` | none | Intentionally public: public-facing input to a private decision. |
| `/v1/ingress/routes*` | ingress bearer token | Reveals every node's address for every host. |
| `/v1/storage/**` | ingress bearer token | Carries private keys in both directions. |
| everything else | node, operator or workload token | Roles and project scopes limit what each may do. |

Both privileged surfaces live on the node's own listener. The ingress bearer token is all an ingress ever holds. The ingress enforces the rest of that boundary itself: it never proxies either prefix through the public platform API apex.

`/.well-known/celld/health` is the application runtime's health endpoint, not the Scafo node/API one.

Registry conditional writes prevent lost updates. Coordinator leases and fences protect stale placement decisions and other lease-gated work.

Node API and runtime listeners default to loopback. Wider binds require an explicit private-network or WireGuard transport decision.

## Limitations

### No OS sandboxing

Builds and runtime processes are not OS-sandboxed from the daemon or from each other. Worker egress can reach any address visible to its network namespace.

### Celld's operator API

Celld's internal operator API is mostly unauthenticated. Keep it on a private network or overlay; do not expose it publicly. See Celld's [security guidance](https://github.com/denoland/celld/blob/main/docs/security.md).

### Credentials reach the runtime

Celld and bucket credentials are administrative authority. Celld child processes receive fleet credentials. Scafo provides no OS credential boundary against trusted-workload compromise or native escape.

### The bucket is an availability boundary

The bucket is both the durable registry and the availability boundary. It must support conditional writes and provide reliable, low-latency lease traffic. Scafo cannot make an unreliable object store highly available.

### Celld lease retry

Celld 0.4.0 can self-fence during intermittent store failures: after an ambiguous renewal that reads the unchanged lease, it waits a third of the lease lifetime before retrying. Scafo preserves Celld's default. Track [Celld issue #182](https://github.com/denoland/celld/issues/182).

### Deploy bounds are scheduling, not admission

Deploy admission bounds artifact bytes and entries, retained builder output, node and project concurrency and queue depth, staged bytes, and receive/queue/task deadlines. These are **scheduling** bounds, not OS resource admission. Apply host or container CPU, memory, process, filesystem and network limits.

### Supervision requirements

`scafo sail` closes deploy intake, cancels deploy work, joins builder cleanup, then drains runtimes on `SIGINT`/`SIGTERM`.

- On a bare host, use the installer's systemd unit or an equivalent cgroup-owning supervisor that terminates the daemon first, removes remaining builders on exit or timeout, and allows at least 50 seconds of shutdown grace. If `CELLD_SHUTDOWN_TOTAL_MS` is larger, allow at least 10 additional seconds.
- In containers, keep the direct Node entrypoint as **PID 1 in a private PID namespace**. Do not use host PID mode or a persistent wrapper.

Physical-host failure remains outside process-code guarantees.

### Operator responsibilities

Application authentication, public TLS, and ingress policy remain the operator's.

## Deploying safely

- Keep node, runtime-peer and operator traffic on a private network or encrypted overlay. Publish only intended application ingress endpoints.
- Protect bucket, node, ingress-token and deployment credentials as administrative secrets. Use a bucket scoped to one installation.
- Test object-store conditional writes, latency and failure behaviour before production use.
- Configure Celld runtime policy through `runtime.celldEnv`, `--celld-env` or `SCAFO_CELLD_ENV`. Scafo adds no Celld policy defaults.
- If intermittent multi-second stalls are acceptable with slower failure detection, set `CELLD_TTL_MS=30000` consistently on every node. Celld then renews every 10 seconds and unplanned takeover can take up to 30 seconds.
- Pin and review the Scafo build and the current Celld release. Review Celld's [security](https://github.com/denoland/celld/blob/main/docs/security.md), [limitations](https://github.com/denoland/celld/blob/main/docs/limitations.md) and [Cloudflare compatibility](https://github.com/denoland/celld/blob/main/docs/cloudflare-compat.md) notes before upgrading.

## The Celld boundary

Scafo requires Celld 0.4.0 and creates one Celld fleet per environment.

| Celld owns | Scafo owns |
|---|---|
| Deployment adoption | Registry |
| Application health | Authorization |
| Cells | Placement |
| Runtime resource policy | Supervision, deploy intake, and the routing every ingress reads |

Celld exposes one current deployment per fleet. Scafo records a monotonic deployment revision, not a selected version; it provides no old-build routing and no historical deployment selector. See [Celld issue #181](https://github.com/denoland/celld/issues/181).

Scafo does not add a raw TCP bridge or transparent tunnel around missing Celld APIs.

::warning
Hostile workload isolation is not available. Do not infer it from scopes, deployment separation, or ingress routing.
::
