# Install

> Four ways to get Scafo onto a machine: the npm CLI, the Linux installer, the container image, and compiled binaries.

Scafo runs nodes on Linux only. The CLI half runs anywhere Node.js does.

## CLI

```sh
npm install --global scafo
```

This installs the same binary as everything below; it is enough for `deploy`, `env`, `project`, `varset`, `trust`, `operator`, `remote`, `fleet`, `metrics` and `traces`. Running a node also needs Celld, an ingress and, for a tunnel, `wireguard-tools`.

## Linux installer

```sh
curl -fsSLO https://raw.githubusercontent.com/sandros94/scafo/main/scripts/install.sh
sh install.sh
```

The installer selects the latest GitHub release unless `SCAFO_VERSION` names an exact one.

### What it downloads

Every download is SHA-256 verified before anything on the host changes. A sidecar `.sha256` file provides integrity; set the matching checksum variable to authenticate a latest-release download.

| Binary | Source |
|---|---|
| `scafo` | GitHub releases of `sandros94/scafo` |
| `celld` | Celld 0.4.1, pinned by checksum in the script |
| `caddy` | `scafo-caddy` from `sandros94/scafo-ingress` releases, pinned by checksum |
| `esbuild` | esbuild 0.28.2, pinned by checksum |

The ingress it installs is `scafo-caddy` and only `scafo-caddy`: it carries `caddy.storage.scafo` and the `scafo` dynamic-upstreams source. Upstream Caddy has neither module.

### Environment variables

| Variable | Effect |
|---|---|
| `SCAFO_VERSION` | Install an exact release instead of the latest. |
| `SCAFO_INSTALL_BASE` | Base URL the `scafo` artifacts are fetched from. |
| `SCAFO_SHA256` | Expected checksum of the `scafo` binary. |
| `SCAFO_CADDY_BASE` | Base URL the `scafo-caddy` artifacts are fetched from. |
| `SCAFO_CADDY_SHA256` | Expected checksum of the `scafo-caddy` binary. |
| `SCAFO_INSTALL_BIN_DIR` | Destination directory for the binaries. |
| `SCAFO_INSTALL_MIRROR` | Mirror for the pinned third-party artifacts. |
| `SCAFO_INSTALL_SKIP_UNITS=1` | Install binaries only; write no systemd units. |

Without an explicit `SCAFO_INSTALL_BIN_DIR`, the destination is `/usr/local/bin` when the script runs as root or has non-interactive `sudo`, and `~/.local/bin` otherwise.

### What it writes as root

Units are written only when the script runs as root on a systemd host and `SCAFO_INSTALL_SKIP_UNITS` is unset.

| Path | Contents |
|---|---|
| `/etc/systemd/system/scafo-node.service` | The node unit. |
| `/etc/systemd/system/caddy.service` | The ingress unit; receives the ingress token through systemd `LoadCredential=`. |
| `/etc/scafo/node.env` | Mode `0600`. Bucket credentials and every other node setting, commented. Preserved across reinstalls. |
| `/etc/scafo/caddy.json` | The ingress configuration. Never rewritten if it already exists. |
| `/var/lib/scafo` | Mode `0700`, owned by the `scafo` user. Node identity, ingress token, WireGuard material, install manifest. |
| `/var/log/scafo-ingress/` | Where Caddy writes its access log when asked to. |
| `/var/lib/caddy` | The ingress unit's `StateDirectory`. Certificates are not here; they are in the bucket. |
| `/var/lib/scafo/install.manifest` | What this run installed, read by `uninstall.sh`. |

Two service accounts are created when missing: `scafo` and `caddy`.

::important
The installer does not start a node. Fill in `SCAFO_S3_ENDPOINT`, `SCAFO_S3_BUCKET`, `SCAFO_S3_ACCESS_KEY`, `SCAFO_S3_SECRET_KEY` and `SCAFO_PLATFORM_DOMAINS` in `/etc/scafo/node.env` first, then `systemctl enable --now scafo-node.service`.
::

::note
On the first boot the ingress unit fails and retries until the node mints the ingress token. `Restart=on-failure` with `StartLimitIntervalSec=0` is what carries it; `243/CREDENTIALS` in the first moments of the journal is expected.
::

### Refusals

The installer stops rather than installing on a host it cannot support:

- Not Linux.
- An architecture other than `x86_64`/`amd64` or `aarch64`/`arm64`.
- A musl C library (Alpine and similar) — every installed binary is linked against glibc. Use the container image there.

WireGuard is never installed: a tunnel needs a kernel module and `NET_ADMIN`. Install `wireguard-tools` with the host package manager.

### Uninstall

```sh
sh uninstall.sh [--purge] [--dry-run] [--bin-dir <dir>]
```

| Flag | Effect |
|---|---|
| *(none)* | Removes units, executables and `/etc/scafo`; preserves `/var/lib/scafo`, ingress state, logs and created accounts. |
| `--purge` | Also removes the state directory, including this node's keypair. |
| `--dry-run`, `-n` | Prints every removal and performs none. |
| `--bin-dir <dir>` | Where the binaries were installed, when the manifest cannot say. |

Neither mode changes the bucket or its registry. A node that stops is counted out of placement on its own.

## Container image

```
ghcr.io/sandros94/scafo:<version>
```

| Tag | Meaning |
|---|---|
| `:<version>` | A release. |
| `:edge` | Every commit on `main`. |

The image bundles Scafo, Celld 0.4.1 and esbuild on a `node:24-slim` base with `ca-certificates`.

| Property | Value |
|---|---|
| User | `scafo`, uid/gid `10001` |
| Home and state dir | `/var/lib/scafo`, mode `0700`; `SCAFO_STATE_DIR` points at it |
| esbuild | `/usr/local/bin/esbuild`, with `CELLD_ESBUILD` set to it |
| Celld | `/usr/local/bin/celld` |
| Exposed port | `7400` |
| Entrypoint | `node /app/dist/cli/index.mjs`, default command `sail` |
| Healthcheck | `scafo health`, every 5s, 3s timeout, 30s start period, 3 retries |
| Stop signal | `SIGTERM` |

::warning
Keep the direct Node entrypoint as PID 1 in a private PID namespace. Do not use host PID mode or a persistent wrapper. Configure at least 50 seconds of shutdown grace, or `CELLD_SHUTDOWN_TOTAL_MS` plus at least 10 seconds when that is raised.
::

The matching ingress image is `ghcr.io/sandros94/scafo-caddy:<version|edge>`, in a lean flavour and a `-dns` flavour carrying DNS-01 provider plugins.

Image details and container requirements.
::

## Binaries

```sh
pnpm compile
```

Produces `build/scafo-linux-amd64` and `build/scafo-linux-arm64`, each with a `.sha256` file. `pnpm compile linux-amd64` builds one target. Celld, an ingress and WireGuard tools remain separate prerequisites.

## Bootstrap an operator key

Nothing can be deployed until the fleet trusts a key. With the bucket settings exported into your shell:

```sh
scafo operator keygen --register
```

The key lands in `./scafo-operator.json`, which is where `scafo deploy` looks for it. `--register` writes the public half straight into the registry, with no daemon involved. This bucket-side path admits admin tier only: an operator-tier key needs a project scope, and only the node API can grant one.
