# CLI

> Every command, subcommand, argument and flag of the `scafo` binary.

One executable is both the node daemon and the operator commands. Top-level commands, in the order `scafo --help` prints them:

`sail`, `health`, `remote`, `operator`, `fleet`, `project`, `deploy`, `env`, `deployment`, `trust`, `metrics`, `traces`, `wg`.

Two hidden aliases remain from a rename: `scafo up` → `scafo sail`, and `scafo keygen` → `scafo operator keygen`. Both still work, print a deprecation line before running, are hidden from help, and are removed at launch.

## Exit behaviour

Every command wraps its work in a single failure reporter.

| Outcome | stderr | Exit code |
| --- | --- | --- |
| Success | command's own output on stdout | 0 |
| A scafo failure | `scafo: <title>[: <detail>] [urn:scafo:<code>]` | 1 |
| Anything else | `scafo: unexpected failure: <message chain, up to 4 causes>` | 1 |

The bracketed `urn:scafo:<code>` is the stable contract; see [/reference/errors](/reference/errors). A failure answered by a node is re-rendered from the node's own problem document, so the code the node chose is the code printed.

## Shared flag groups

Referenced by name in each command below.

### Bucket flags

Where the registry lives, taken exactly as `scafo sail` takes them. All strings.

| Flag | Description |
| --- | --- |
| `--config` | Path to `scafo.config.jsonc` |
| `--endpoint` | S3-compatible endpoint URL |
| `--region` | Signing region of the bucket |
| `--bucket` | Bucket holding the registry |
| `--prefix` | Key prefix within the bucket |
| `--access-key` | Bucket access key id |
| `--secret-key` | Bucket secret access key |

Each also reads from the environment and the config file; see [/config](/config) for precedence and variable names.

### Remote flags

Which installation an invocation reaches, and who is speaking. All strings.

| Flag | Description |
| --- | --- |
| `--config` | Path to `scafo.config.jsonc`, read for its `remote` pin |
| `--remote` | Remote to act on, out of this operator's home |
| `--node` | Node to reach, instead of the remote's first endpoint |
| `--key` | Operator key to sign with: a key file from `scafo operator keygen`, a portable file from `scafo remote export`, or an inline `base64:` value of one |

Resolution order: the key comes from `--key`, then `SCAFO_OPERATOR_KEY`, then the remote. The endpoint comes from `--node`, then whatever a portable key carried, then the remote. The remote comes from `--remote`, then `SCAFO_REMOTE`, then the config file's `remote` pin, then the only remote registered; a home holding several with nothing to choose between them prompts on a TTY and is refused (`invalid-input`) otherwise.

### `--json`

Boolean. Prints the records as JSON instead of a table. Accepted by `fleet nodes`, `project list`, `metrics` and `traces`.

## `scafo sail`

```
scafo sail [flags]
```

Join this machine to the fleet and serve the node API. Talks to the **bucket** (registers the node, reads and writes the registry) and **binds the node API listener**. Prints `scafo <version> listening on <url> as node "<id>"` once serving.

Every flag is the kebab-case name of a configuration setting, plus `--config`. Flags win over environment variables, which win over the config file. Booleans support `--no-` negation; a boolean nobody wrote leaves the environment and the file to decide.

| Flag | Type | Description |
| --- | --- | --- |
| `--config` | string | Path to `scafo.config.jsonc` |
| `--endpoint` | string | S3-compatible endpoint URL |
| `--region` | string | Signing region of the bucket |
| `--bucket` | string | Bucket holding the registry |
| `--prefix` | string | Key prefix within the bucket |
| `--access-key` | string | Bucket access key id |
| `--secret-key` | string | Bucket secret access key |
| `--node-id` | string | Id this node registers under |
| `--state-dir` | string | Directory this node keeps its identity in |
| `--node-labels` | string | What this node is, for environments to select on (`region=eu-west-1,tier=fast`) |
| `--listen` | string | `host:port` the node API binds to |
| `--advertise` | string | `host:port` other nodes reach this one at |
| `--transport` | string | What carries peer traffic (`wireguard`, `none`) |
| `--wg-address` | string | This node's tunnel address with its prefix length (`10.83.0.1/24`) |
| `--wg-endpoint` | string | `host:port` peers send this node's tunnel traffic to |
| `--wg-port` | string | UDP port the tunnel interface listens on (`51820`) |
| `--platform-domains` | string | Comma-separated apex domains to serve |
| `--ingress-token` | string | Token(s) admitted on `/v1/ingress` and `/v1/storage`, instead of one this node mints. `new,old` admits both while a rotation is in flight, and the first is written to the state directory's ingress-token file. Restart the daemon before reloading the ingress |
| `--celld-bin` | string | Executable that runs an environment |
| `--celld-env` | string | Upstream Celld variables for every runtime process, `NAME=value,NAME2=value2`; a value cannot contain a comma here — write those as `runtime.celldEnv` in the config file |
| `--port-range-start` | string | First port runtime processes use |
| `--bind-host` | string | Address runtime processes bind their listeners to |
| `--artifact-bytes` | string | Maximum compressed and expanded bytes per deploy artifact |
| `--archive-entries` | string | Maximum entries per deploy archive |
| `--active-tasks` | string | Maximum active deploy tasks on this node |
| `--project-active-tasks` | string | Maximum active deploy tasks for one project |
| `--queued-tasks` | string | Maximum receiving and queued deploys |

| `--staged-bytes` | string | Maximum staged deploy bytes on this node |
| `--project-staged-bytes` | string | Maximum staged deploy bytes for one project |
| `--receive-timeout-ms` | string | Artifact receive deadline in milliseconds |
| `--queue-timeout-ms` | string | Queued deploy deadline in milliseconds |
| `--task-timeout-ms` | string | Active deploy deadline in milliseconds |
| `--output-bytes` | string | Subprocess output tail retained in memory |
| `--observability` / `--no-observability` | boolean | Report what this node does: emit its own events, and give every runtime process `CELLD_OTEL=1` unless `runtime.celldEnv` already states it |
| `--ingress-access-log` | string | File the ingress writes its JSON access log to; the node follows it and counts requests, bytes, statuses and latencies per environment. Needs `--observability` |
| `--api-public` / `--no-api-public` | boolean | Serve the fleet's API at each platform domain's own apex, so any node is reachable at one well-known name (default on; `--no-api-public` leaves the apex unrouted and without a certificate). `/v1/storage` and `/v1/ingress/routes` are never reachable there |
| `--json-bytes` | string | Maximum bytes accepted by a JSON API control request |
| `--traefik-entrypoints` | string | Traefik entryPoints the published routers attach to (`web,websecure`) |

## `scafo health`

```
scafo health [bucket flags] [--listen] [--transport] [--wg-address]
```

Ask this machine's node whether it is serving. Talks to the **local node API** — `GET /.well-known/scafo/health`, with a 2-second deadline. It is what the image's `HEALTHCHECK` runs.

| Flag | Type | Description |
| --- | --- | --- |
| bucket flags | string | As above; the loader asks for them |
| `--listen` | string | `host:port` the node API binds to |
| `--transport` | string | What carries peer traffic (`wireguard`, `none`) |
| `--wg-address` | string | This node's tunnel address with its prefix length (`10.83.0.1/24`) |

It resolves `node.listen` exactly as `scafo sail` does, from the environment and the config file, so the probe follows the listener. A setting given to the daemon only on its command line must be repeated here.

Failures are `not-found`: *Node is not answering* (nothing answered within the deadline) or *Node is not healthy* (something answered, but not the health document this node serves). Both name the URL that was asked.

## `scafo remote`

Name the installations you can reach, and hold the key that speaks to each. Everything here acts on the **operator home** (a local directory), except `--register`, which writes to the **bucket**.

::warning
`--endpoint` here is a **node daemon URL**, not an S3 endpoint. The bucket for `--register` is configured through the config file and the environment instead.
::

### `scafo remote add`

```
scafo remote add [name] --endpoint <url[,url]> [flags]
```

Register a remote, with a key of its own.

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | positional | no | Name to reach this remote by |
| `--endpoint` | string | — | Base URL of one of its nodes; comma-separated for several |
| `--key` | string | no | Reuse a key already in this home, instead of minting a fresh one |
| `--from` | string | no | Import a portable file: a path, or an inline `base64:` value |
| `--register` | boolean | no | Record the key's public half in the registry, bucket-side (admins only) |
| `--role` | string | no | Tier to register at: `admin` (the first key is always one, and this path admits no other — an operator-tier key needs a project scope, which only the wire path can give it) |
| `--config` | string | no | Path to `scafo.config.jsonc`, for `--register` |

Without `--register`, a freshly minted key is only local: register it later, or have an admin admit it with `scafo operator enroll`.

### `scafo remote list`

```
scafo remote list
```

Print the remotes this operator can reach. No arguments.

### `scafo remote remove`

```
scafo remote remove <name>
```

Unregister a remote, and its key if nothing shares it. `name` is a required positional. Nothing is said to the installation itself: the key it holds stays accepted there until it is removed from the registry.

### `scafo remote export`

```
scafo remote export <name> [--out <file>]
```

Write a remote out as one portable, self-contained file.

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | positional | yes | Remote to write out |
| `--out` | string | no | File to write it to, readable by its owner alone |

## `scafo operator`

The people: every human here is an operator, and admin is a role an operator holds.

### `scafo operator keygen`

```
scafo operator keygen [bucket flags] [--out <file>] [--id <op-...>] [--register] [--role <tier>]
```

Write an operator key file for the node API. To set an operator up, use `scafo remote add` instead. Talks to **nothing** unless `--register` is given, which writes the public half straight to the **bucket** — the bootstrap path, needing no daemon.

| Flag | Type | Description |
| --- | --- | --- |
| bucket flags | string | As above, for `--register` |
| `--out` | string | File to write the key pair to (`scafo-operator.json`) |
| `--id` | string | Id to register the key under (`op-<hex>`) |
| `--register` | boolean | Record the public half in the registry |
| `--role` | string | Tier to register at: `admin` (the first key is always one, and this path admits no other) |

### `scafo operator show`

```
scafo operator show [--config] [--remote] [--key]
```

Print this operator's public half, to send to an admin. Local only. The document goes to **stdout** and the explanatory line to **stderr**, so `scafo operator show > me.json` produces a file an admin can enrol as it stands.

| Flag | Type | Description |
| --- | --- | --- |
| `--config` | string | Path to `scafo.config.jsonc`, read for its remote pin |
| `--remote` | string | Remote whose key to show, out of this operator's home |
| `--key` | string | Key to show instead: a key file, a portable file, or an inline `base64:` value |

### `scafo operator enroll`

```
scafo operator enroll <pubkey> [--remote <name>] [--role] [--projects] [--node] [bucket flags]
```

Admit somebody else's public key to a fleet. Two paths, never chosen by default: the **wire** path (`POST /v1/operators` on a node, authorized by an admin key) and the **bucket** ceremony (authorized by the bucket credential, for an installation being seeded or one that has locked every operator out).

| Argument | Type | Required | Description |
| --- | --- | --- | --- |
| `pubkey` | positional | yes | Public document from `scafo operator show`: a path, an inline `base64:` value, or the document itself |
| `--remote` | string | no | Remote whose node admits the key, admin-authed |
| `--role` | string | no | Tier to admit it at: `admin` or `operator` |
| `--projects` | string | no | Projects the key may name, comma-separated, or `*` for every project; required for an operator-tier key (wire path only) |
| `--node` | string | no | Node to reach, instead of the remote's first endpoint |
| bucket flags | string | no | Selects the bucket ceremony when any of them is given |

The bucket ceremony seeds and recovers **admins**: it is never scoped and never at the operator tier.

### `scafo operator rotate`

```
scafo operator rotate [--config] [--remote] [--node] [--keep-old] [--purge-old]
```

Replace the key a remote signs with, proving the new one before dropping the old. Talks to the **node API**.

| Flag | Type | Description |
| --- | --- | --- |
| `--config` | string | Path to `scafo.config.jsonc`, read for its remote pin |
| `--remote` | string | Remote to act on, out of this operator's home |
| `--node` | string | Node to reach, instead of the remote's first endpoint |
| `--keep-old` | boolean | Stop after the flip, leaving the old key trusted as well |
| `--purge-old` | boolean | Delete the old key file once it is untrusted |

### `scafo operator revoke`

```
scafo operator revoke --id <id> [--config] [--remote] [--node]
```

Stop a fleet trusting a key that is not your own. Talks to the **node API**.

| Flag | Type | Required | Description |
| --- | --- | --- | --- |
| `--id` | string | yes | Key to stop trusting; not your own |
| `--config`, `--remote`, `--node` | string | no | As for `rotate` |

### `scafo operator list`

```
scafo operator list [--config] [--remote] [--node]
```

Print the operator keys a fleet trusts, and their tiers. Talks to the **node API**. An admin sees every key; an operator sees only its own rotation lineage.

## `scafo fleet`

The machines of one installation: what is out there, and what it is doing.

### `scafo fleet nodes`

```
scafo fleet nodes [bucket flags] [--json]
```

List the machines in this fleet, and which are answering. Reads the **bucket** directly; no node has to be up. Every row is judged against one `now`, so nodes never appear to drift apart. Columns: `NODE`, `STATE`, `SEEN`, `API`, `CELLD`, `SCAFO`, `LABELS`; above the table, one line per binary counts nodes per version, newest first, and — while one stands — a line naming the deploy freeze, since when, by whom and why. `--json` carries the same rows, with `versions: { scafo, celld }` where the record has them, and no freeze line.

### `scafo fleet freeze`

```
scafo fleet freeze [remote flags] [--reason <line>]
```

Stop every deploy of this installation, leaving serving alone. **Admin only.** Talks to a **node**, on the authority of an operator key: freezing is an authorization the bucket cannot enforce, so there is no bucket path here. Without a node the refusal is `invalid-input`, *No node to ask*.

| Flag | Type | Description |
| --- | --- | --- |
| remote flags | string | As above |
| `--reason` | string | Why, in one line, printed to everyone whose deploy is refused. At most 200 characters, no newline or control character |

While it stands, every node refuses deploy intake with `deploys-frozen` (409) before anything is created. Serving, reconciliation, retirement and `scafo env delete` carry on untouched.

Freezing twice is one freeze: the first admin's record — stamp and reason — is the one that stands, and the command says so.

```
scafo: deploys are frozen since 2026-09-18T09:12:04.115Z by "op-9f3c": moving every node to Celld 0.5.0 — every deploy is refused with deploys-frozen until "scafo fleet unfreeze"
scafo: deploys were already frozen since 2026-09-18T09:12:04.115Z by "op-9f3c" — every deploy is refused with deploys-frozen until "scafo fleet unfreeze"
```

### `scafo fleet unfreeze`

```
scafo fleet unfreeze [remote flags]
```

Take deploys again after a freeze. **Admin only**, and reaches the installation the same way.

```
scafo: deploys are no longer frozen; nodes accept them again
scafo: deploys were not frozen
```

## `scafo project`

The things this installation hosts. Every subcommand reaches the installation through a **node**, on the authority of an operator key — there is no bucket path. Without a node the refusal is `invalid-input`, *No node to ask*.

All subcommands take the [remote flags](#remote-flags).

| Command | Arguments | Description |
| --- | --- | --- |
| `scafo project list [--json]` | — | List the projects this key reaches, and which of them are blocked |
| `scafo project show <slug>` | `slug` positional, required | Show one project: its state, when it began, its labels |
| `scafo project block <slug>` | `slug` positional, required | Stop serving and deploying a project, reversibly (**admin only**) |
| `scafo project unblock <slug>` | `slug` positional, required | Put a blocked project back into service (**admin only**) |
| `scafo project label <slug> [k=v ...]` | `slug` required; `pairs` trailing positionals, optional | Replace a project's labels, which scafo stores and never reads (**admin only**) |

`show` is answered out of the listing rather than a route of its own: a project this key cannot reach simply reads as `not-found`. `label` **replaces every label** the project carries; passing no pairs clears them.

## `scafo deploy`

```
scafo deploy [dir] --project <slug> [flags]
```

Deploy a built project to a node. Talks to the **node API**: `POST /v1/projects/:project/deploys` with the packed directory as the raw body, then polls the returned `Location` every second until the deploy settles in `deployed` or `failed`.

| Argument | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `dir` | positional | no | `.` | Directory holding the built project |
| `--project` | string | **yes** | — | Project slug to deploy into |
| `--env` | string | no | `production` | Environment to deploy into |
| `--var` | string | no | — | Set a variable in the artifact's runtime config, overriding the config's own `vars`; repeatable. Written `KEY:VALUE` and split at the **first** colon, so a value may contain colons |
| `--bundle` / `--no-bundle` | boolean | no | `true` | Build the Worker entry on the node; `--no-bundle` sets `no_bundle: true` in the artifact's runtime config, for an entry that is already pre-bundled and self-contained |
| `--replicas` | string | no | — | How many nodes serve this environment: a whole number, or `all` |
| `--node-selector` | string | no | — | Labels a node must carry to serve this environment (`region=eu-west-1,tier=fast`) |
| `--node` | string | no | — | Base URL of the node daemon; without it the chosen remote says where |
| `--remote` | string | no | — | Remote to deploy to, out of this operator's home |
| `--key` | string | no | — | Operator key to sign with |
| `--config` | string | no | — | Path to `scafo.config.jsonc`, read for its remote pin |
| `--token` | string | no | — | Bearer token to present instead of signing one; a single-use node token cannot watch |

`--replicas` and `--node-selector` are sent **only when given**: a deploy that names neither leaves whatever the environment already carries exactly as it is. Neither flag can lift a constraint — that is `scafo env selector`.

`--var` and `--no-bundle` edit the project's `wrangler.jsonc` or `wrangler.json` — the CLI reads it, applies the edit in memory, and packs the result into the archive; the file in the project directory is never written. A `--var` entry replaces the config's own `vars` entry of the same name and leaves every other entry as written; an empty value sets the variable to nothing; a name given twice is refused with `invalid-input`, as is a pair with no colon in it. Names are letters, digits and underscores, never beginning on a digit, and never `__proto__`, `constructor` or `prototype`. A config that already declares `no_bundle: true` needs no flag. With neither flag the archive carries the config byte for byte.

::warning
A value passed with `--var` is visible in the process list and the CI log of the machine running the CLI, and Celld stores variables as plain text in the bucket, so anyone with bucket read access can read them. Celld has no secret store. Keep defaults in the config's `vars`, pass per-environment values from the CI's secret store as `--var`, mask them in CI logs, and treat bucket read access as access to every variable.
::

With no `--node` and no remote, the command refuses with `invalid-input`, *No node to deploy to*.

::warning
A node token is spent by the first request that presents it, so `--token` with one deploys but cannot poll. The refusal during polling is a clarified `auth-invalid`: *Deploy accepted, but it cannot be watched*. Sign with an operator key, or present a workload token the project's trust policy admits, to watch a deploy through to its outcome.
::

## `scafo env`

Retire, restore, target and delete environments. A **node** is asked whenever one is named — by `--node`, or by the remote this operator's home resolved — and otherwise the **bucket** is written directly.

Every subcommand takes the bucket flags plus:

| Flag | Type | Required | Description |
| --- | --- | --- | --- |
| `--project` | string | **yes** | Project the environment belongs to |
| `--env` | string | **yes** | Environment to act on |
| `--node` | string | no | Base URL of a node daemon to ask; without it the chosen remote says where, and without a remote the bucket is written directly |
| `--remote` | string | no | Remote to act on, out of this operator's home |
| `--key` | string | no | Operator key to sign with |

| Command | Extra flags | Description |
| --- | --- | --- |
| `scafo env retire` | — | Stop serving an environment, reversibly |
| `scafo env unretire` | — | Put a retired environment back into service |
| `scafo env selector` | `--set <k=v,...>`, `--clear` | Choose which nodes may serve an environment. `--set` names labels a node must carry (`region=eu-west-1,tier=fast`); `--clear` lets it run on every node again |
| `scafo env delete` | `--force` | Delete a retired environment whose grace has passed. `--force` deletes whatever state it is in, skipping the retirement and grace requirements |

`delete` prints the count and then every store key it removed, one per line.

## `scafo deployment`

Manage what a project's environments have published. One subcommand.

### `scafo deployment prune`

```
scafo deployment prune [bucket flags] --project <slug> --env <name> [--keep] [--older-than] [--yes] [--dry-run]
```

Delete the old Celld deployments of one environment. Writes the **bucket** directly — the deployments live in the environment's Celld fleet, and no node holds this state.

::warning
**Unstable.** Celld keeps every deployment it has ever published and deletes none of them; until it grows a deployment lifecycle of its own, this command is an operator's hands on that space. It warns on **every** run — `scafo: warning: "scafo deployment prune" is subject to change: Celld may grow a native deployment lifecycle (denoland/celld#181), and this command follows upstream when it does` — before anything is read or deleted. `SCAFO_SILENCE_WARNINGS=1` silences that and every other CLI warning; warnings go to stderr, so piped output stays clean.
::

| Flag | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| bucket flags | string | no | — | As above |
| `--project` | string | **yes** | — | Project the environment belongs to |
| `--env` | string | **yes** | — | Environment to prune deployments of |
| `--keep` | string | no | `10` | How many of the newest deployments to keep. A whole number, zero or more; anything else is `invalid-input`, *Invalid --keep* |
| `--older-than` | string | no | `24h` | Only delete deployments older than this: `30d`, `12h`, `45m`, a whole number of seconds (`3600`), or `0`. Anything else is `invalid-input`, *Invalid --older-than* |
| `--yes` | boolean | no | off | Delete without asking |
| `--dry-run` | boolean | no | off | Print what would go, and delete nothing |

#### The two gates

**Both are always weighed.** A deployment goes only when it is past the count *and* older than the window; `0` lifts whichever gate it is given to, and neither can be lifted by leaving the flag out. A deployment scafo has no record of is weighed as the oldest thing in the fleet.

| Reason a deployment stays | Printed as |
| --- | --- |
| A Celld pointer names it — the fleet-wide selector, or a script's own | `current, the fleet's selector points at it` |
| Among the newest `--keep` | `within the newest 10 deployments` |
| Younger than `--older-than` | `younger than 24h` |

A pointer protects absolutely: what a pointer names is never a candidate, whatever the two gates say. A fleet whose fleet-wide pointer is missing or unreadable is refused outright with `store-nonconforming` rather than pruned against no protection at all.

#### Asset blobs

Deployments share content-addressed asset blobs under the environment's `deploy-blobs/` prefix. After the deployments are weighed — and measured against the set that **stays**, not the one that goes — a blob no kept deployment's `assets.json` references is collected, once it is older than the same `--older-than` window. A blob whose age the store did not report is treated as too young to touch.

An `assets.json` that cannot be read, is not an object, has no `entries`, or names an unusable digest refuses the whole plan with `store-nonconforming`: scafo will not delete a blob beside a deployment whose references it cannot read.

::warning
`--older-than 0` lifts the age gate on the blobs too, and prune says so before it prints the plan: *a deploy in flight uploads its files before it is visible, and pruning now can delete one that is happening; do not prune while anyone deploys.* The window is the only thing that tells an unreferenced blob from one that is about to be referenced.
::

#### What it never touches

Prune weighs only what Celld wrote as a deployment: `deploy/<script>/<version>/`, with a script name Celld would have accepted and a hexadecimal version id. Anything else beneath `deploy/` is left where it is, and two keyspaces are skipped by prefix rather than by the look of their names:

| Prefix | Why |
| --- | --- |
| `deploy/images/` | Container images Celld saved, shared by every deployment that runs one |
| `deploy/queues/` | A queue's consumer attachment, which outlives the deploy that wrote it |

#### Asking, and the answers

A real run prints the plan — one line per deployment, then the blobs — and then asks:

```
Delete 3 deployments (41 objects) and 12 asset blobs of "shop/production"? [y/N]
```

Only `y` or `yes`, in any casing, is consent. `--yes` answers ahead of the question. A dry run and an empty plan ask nothing. A run whose input is **not a terminal** and that was not given `--yes` refuses with `invalid-input`, *Nothing to answer with*, rather than taking silence for consent.

Deletion order is the record before its objects, and the blobs last. The pointers are re-read before **every** deployment's deletion: a pointer that has moved onto a selected deployment refuses the run with `cas-conflict`, *Deployment is in use again*, and nothing of that deployment is deleted — plan the prune again.

#### Verified Celld releases only

Prune reads and deletes inside Celld's own part of the bucket, in formats Celld owns and changes between releases. It therefore plans nothing — a `--dry-run` included — unless two checks hold, and there is no flag that lifts either:

| Check | Refused when |
| --- | --- |
| Release | Any node that is still answering reports a Celld release this build of scafo was not verified against (today: `0.5.0`), or reports none; or **no node is answering at all**, because then nothing says which release wrote the bucket. Records of nodes that stopped answering are ignored. |
| Format | Any deployment's `manifest.json` carries a `schema_version` or a required feature this build does not know, any `assets.json` it reads carries an unknown `schema_version`, or a manifest is there but cannot be read. Every deployment the plan lists is checked, kept and deleted alike. |

Both are `capability-missing`: the detail names what was found, what this build is verified against, and that nothing was planned or deleted. A newer scafo, verified against that release, is what lifts it. A version directory with no `manifest.json` is a deploy in flight — Celld writes the manifest after the files — and is weighed by the age window like anything else.

## `scafo trust`

Manage which CI issuers may deploy a project. Writes the **bucket** directly, because a trust policy is usually set up before there is a node to ask.

All subcommands take the bucket flags plus `--project` (string, **required**).

| Command | Extra flags | Description |
| --- | --- | --- |
| `scafo trust set` | `--issuer` (**required**), `--subject` (**required**), `--audience` | Trust an issuer's subjects to deploy a project |
| `scafo trust show` | — | Print the issuers a project trusts |
| `scafo trust remove` | `--issuer` (**required**) | Stop trusting an issuer |

| Flag | Description |
| --- | --- |
| `--issuer` | Issuer URL, as its tokens carry it in `iss` |
| `--audience` | Audience the workload requests its token for; defaults to `scafo` |
| `--subject` | Subject pattern to trust, `*` matching any run of characters; comma-separated for several |

## `scafo metrics`

```
scafo metrics [bucket flags] [--project] [--env] [--since] [--json]
```

What the fleet served, per project and environment. Read **straight out of the bucket**: no node is asked and none has to be up.

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--project` | string | — | Only this project |
| `--env` | string | — | Only this environment |
| `--since` | string | `1h` | How far back to read: a duration (`90s`, `15m`, `1h`, `7d`) or an ISO-8601 instant |
| `--json` | boolean | off | Print the summary as JSON instead of a table |

The snapshots are monotonic totals per node, so a window is a subtraction. Three distinct silences are reported distinctly: nothing was ever written, something was written outside the window, or the nodes observe themselves and count no requests.

## `scafo traces`

```
scafo traces [bucket flags] [--project] [--since] [--limit] [--all] [--json]
```

What the nodes did, in order. Read **straight out of the bucket**.

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--project` | string | — | Only what belongs to this project |
| `--since` | string | `1h` | How far back to read: a duration or an ISO-8601 instant |
| `--limit` | string | `200` | Events to show at most, newest kept; must be a whole number of at least 1 |
| `--all` | boolean | off | Include the reconcile loop's own passes, which every node emits every 5s whether or not anything happened |
| `--json` | boolean | off | Print the events as JSON instead of lines |

Reconcile-pass events are held back by default so they cannot fill the window; how many were held back is always said.

## `scafo wg`

Set up and refresh this node's WireGuard tunnel. Reads and writes the **bucket** (publishes this node's public half, reads every peer's) and writes local files. It never brings the interface up: run `wg-quick` yourself.

Both subcommands take the same arguments.

| Flag | Type | Description |
| --- | --- | --- |
| bucket flags | string | As above |
| `--node-id` | string | Id this node registers under |
| `--state-dir` | string | Directory this node keeps its identity in |
| `--transport` | string | What carries peer traffic (`wireguard`, `none`) |
| `--listen` | string | `host:port` the node API binds to |
| `--advertise` | string | `host:port` other nodes reach this one at |
| `--wg-address` | string | This node's tunnel address with its prefix length (`10.83.0.1/24`) |
| `--wg-endpoint` | string | `host:port` peers send this node's tunnel traffic to |
| `--wg-port` | string | UDP port the interface listens on (`51820`) |
| `--stdout` | boolean | Print the configuration instead of writing it |

| Command | Description |
| --- | --- |
| `scafo wg init` | Set this node up on the tunnel and render its interface configuration. Sources or generates a keypair, publishes the public half, then renders |
| `scafo wg peers` | Re-render the interface configuration from the nodes now registered. Reads the keypair, never makes one; a state directory holding none is `invalid-input` |

With `--stdout` the configuration is the only thing on stdout; everything else goes to stderr, so `--stdout > wg0.conf` captures a file `wg-quick` can parse. Without it, the file is written owner-readable inside the state directory and the command prints the `wg-quick up` line to run.

A node whose transport is not `wireguard` is refused with `invalid-input`, *This node runs no WireGuard tunnel*.
