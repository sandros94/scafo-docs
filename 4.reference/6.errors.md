# Errors

> The problem-document format, every error code, and how each surface renders one.

Every failure scafo surfaces carries one of nineteen codes. **The code is the stable contract: messages may change, codes may not.**

## Problem documents

The node API answers every failure as an RFC 9457 problem document.

```
HTTP/1.1 409 Conflict
content-type: application/problem+json

{
  "type": "urn:scafo:project-blocked",
  "title": "This project is blocked",
  "status": 409,
  "detail": "\"shop\" has been blocked by an admin of this fleet: it is served nowhere and accepts no deploys until the block is lifted, and nothing of it has been deleted — ask whoever administers this installation"
}
```

| Member | Type | Notes |
| --- | --- | --- |
| `type` | string | `urn:scafo:<code>`. Always present |
| `title` | string | The failure's message. Always present |
| `status` | number | The HTTP status. Always present |
| `detail` | string? | Human-readable specifics, safe to expose. Present when the throw site supplied one |

Two answers are not scafo failures:

| Situation | Document |
| --- | --- |
| A transport-layer HTTP error the handler did not raise | `{ "type": "about:blank", "title": …, "status": … }` |
| An unhandled internal failure | `{ "type": "urn:scafo:internal", "title": "Internal Server Error", "status": 500 }`, with the real error logged and never exposed |

A `deploy-overloaded` answer additionally carries `retry-after: 1`.

## Code table

| Code | HTTP | Meaning, and where it is raised |
| --- | --- | --- |
| `auth-invalid` | 401 | Authentication failed. **Every** token failure, whatever the cause: a missing or malformed `Authorization` header, a wrong `alg`, an unknown `kid`, a bad signature, an expired or not-yet-valid token, a lifetime over 60 s, a replayed `jti`, a wrong ingress token, a workload token that does not verify, a project with no trust policy, an issuer that project does not name, or an operator whose registry record is no longer current |
| `auth-scope` | 403 | Authorization by tier or project scope. A project outside an operator key's scope; a node token on an operator-only route; registering a key beyond the caller's tier or reach; granting `*` as a non-admin; superseding a key that is not the caller's own; revoking a key an operator-tier caller was not registered to replace; blocking or labelling a project as a non-admin |
| `trust-mismatch` | 403 | The token holds up, but the project's trust policy does not admit its issuer or subject. The one rejection that is authorization rather than authentication, and the one a CI job can act on |
| `cas-conflict` | 409 | A conditional write was refused by the store; a named lock is already held; or a state a command asserted did not hold after the call (a project still blocked, an environment still retired) |
| `capability-missing` | 409 | This node cannot do the thing at all: no deploy runner configured, no file-backed artifact stager, no signing key with which to reach the coordinator, a publish command that could not be run, or a POSIX process group that could not be created, stopped or observed |
| `placement-unavailable` | 409 | Placement cannot be satisfied: no live node, or no free port pair in the configured range |
| `project-blocked` | 409 | An admin of the fleet has stopped the project. A conflict rather than a forbidden: nothing is wrong with the caller or its key, and the same request works unchanged the moment the block is lifted |
| `draining` | 503 | Nothing is refusing you — this node cannot answer right now. The fleet's routing is not known yet (no reconcile pass has completed); no node is coordinating; or a forwarded deletion landed on a node that does not coordinate either |
| `deploy-overloaded` | 429 | The deploy scheduler's capacity is exhausted. Answered with `retry-after: 1` |
| `deploy-timeout` | 408 | A deploy receive, queue or task deadline elapsed |
| `store-nonconforming` | 500 | The bucket is not behaving as the registry requires: a stored object that is not valid JSON, registry meta of an unknown version, a store that does not honour conditional writes or ranged reads, a listing cut short, a missing ETag, a TLS object that is not a storage envelope, or a publish that reported no version |
| `not-found` | 404 | The thing named does not exist: an object, a deploy id, a stored TLS key or prefix, a host that is not served, an ingress format this node does not render, a remote that is not registered, or a node that is not answering |
| `immutable` | 409 | Something that may only be written once was written again, or an identity was changed: a node id, a project identity, an existing build, varset or environment |
| `lease-lost` | 409 | Authority to write was lost partway: the coordinator lease is no longer held or could not be renewed, a placement fence is stale, a named lock is no longer held, or publish authority was lost |
| `reference-held` | 409 | The name or thing is spoken for: an id belonging to another identity, a node id belonging to an operator key (or the reverse), a domain claimed by another environment, or the last trusted operator key / last admin key, which cannot be revoked |
| `resource-limit` | 413 | An input exceeded a configured bound: a JSON body over `api.jsonBytes`, an artifact over `artifactBytes`, an archive with too many entries, or an archive that expands too large |
| `invalid-slug` | 400 | An id or slug does not match its charset: a project or environment slug, a content id, a node id, an operator id, or a `<project>--<ref>` host label over the slug length limit |
| `invalid-varset` | 400 | A varset key that will not load, an unsupported envelope, a varset that will not decrypt, plaintext that is not JSON, or an environment naming a varset this node has no key for |
| `invalid-input` | 400 | Everything else the caller got wrong: missing or malformed configuration, missing required arguments, malformed request bodies and headers, a bad storage key, an unsupported storage protocol version, a self-revocation, a deploy the node reported as failed, and the fallback for an unrecognized problem type |

## Reading a problem document back

A client turns an answer back into the failure it describes rather than re-labelling it — flattening `trust-mismatch` and `auth-invalid` into one code would throw away the distinction the API is careful to keep.

Every member is checked rather than trusted, because what arrives may have come from a proxy, a load balancer or an error page:

| Situation | Result |
| --- | --- |
| `type` is `urn:scafo:<known code>` | That code |
| `type` is `urn:scafo:<code this build has never heard of>` | **`invalid-input`**, the fallback. A newer node naming a code this one does not know is a real thing and not worth crashing over |
| `type` is missing or is not a string | `invalid-input` |
| `title` is missing or is not a string | `"Request failed"` |
| `status` is not an integer | The default status of the resolved code |
| The answer carries no `type` and `title` at all | `invalid-input`, *Node answered `<status>`*, with the method and URL as its detail |

## CLI rendering

Every command wraps its work in one reporter.

| Outcome | stderr | Exit code |
| --- | --- | --- |
| A scafo failure | `scafo: <title>[: <detail>] [urn:scafo:<code>]` | 1 |
| Anything else | `scafo: unexpected failure: <message chain>` | 1 |

The unexpected-failure chain follows `cause` up to four levels deep, because `fetch` reports `TypeError: fetch failed` and puts the refused connection in its cause — a renderer stopping at the top would print nothing an operator could act on.

A failure answered by a node is re-rendered from that node's own problem document, so the code printed is the code the node chose.

## Ingress-side failures

### The Caddy module

The dynamic-upstreams module cannot choose a status code — Caddy's answer to *no upstreams* is `503` — so it records why in `scafo.route` and leaves the answer to a `handle_errors` route.

| `scafo.route` | Meaning |
| --- | --- |
| `ok` | The document named upstreams for this request. A `503` with `ok` means they were all unreachable |
| `unknown` | The fleet does not serve this host |
| `denied` | The host is a platform API host and the path is one the ingress must answer itself. Enforced whatever the error route says |
| `unavailable` | No routing document has arrived yet. Deliberately not `unknown`: a cold start is not a missing deployment |

`scafo.host` carries the normalized host the lookup was keyed by. Answering `denied` the same way as `unknown` is deliberate: a distinct status would confirm that the path exists.

For storage, a `404` is translated into an error wrapping `io/fs.ErrNotExist`, which is what CertMagic checks with `errors.Is` to tell a missing key from a broken backend.

### Traefik

Traefik's http provider logs a failed fetch and **keeps its previous configuration**. A `503 urn:scafo:draining` from a node that has not finished its first reconcile pass is therefore a pause in the provider rather than a withdrawal of every route — treat it as any other fetch failure, never as an empty document.

The renderer answers `{}` rather than empty maps when there is nothing to publish, because empty maps make Traefik retain stale provider configuration.
